# M1 前端查询工作台子 PRD

> 版本：v0.1
> 所属总 PRD：`prd.md`
> 共享契约：`docs/contracts/query-api.md`
> 推荐实现客户端：前端 AI coding 客户端
> 技术栈决策：Vue 3 + Vite + Tailwind CSS。

## 1. 目标

实现 M1 阶段的公开查询工作台，让用户可以通过浏览器查询 AI HOT 种子源内容：精选、全部动态、分类、关键词、时间窗、日报和日报归档。

前端只消费本系统后端 API，不直接调用 AI HOT。

## 2. 范围

### 2.1 In Scope

- 公开查询页。
- 精选 / 全部动态切换。
- 分类筛选。
- 关键词搜索。
- 时间窗选择。
- 最新日报和指定日期日报展示。
- 日报归档列表。
- 结果列表、结果卡片、日报 section。
- 空状态、错误态、加载态。
- 重试按钮。
- 移动端适配。
- 使用 mock API 并行开发。

### 2.2 Out of Scope

- 登录、用户中心、权限。
- 数据源管理后台。
- Topic 聚类详情。
- 价值评分详情。
- 背景包和 AI 点评编辑。
- 订阅、推送、Webhook。
- 趋势图表。
- 直接调用 AI HOT。

## 3. 页面结构

M1 只需要一个公开查询工作台页面，可以按组件拆分。

### 3.1 顶部查询区

能力：

- 输入关键词。
- 提交搜索。
- 清空搜索。
- 显示帮助入口。

行为：

- 关键词长度 1 时不请求，提示“关键词至少 2 个字符”。
- 空关键词可查询精选或全部动态。
- 回车触发查询。

### 3.2 模式切换

模式：

- 精选。
- 全部动态。
- AI 日报。
- 日报归档。

行为：

- 默认选中“精选”。
- 只有用户点“全部动态”才请求 `mode=all`。
- AI 日报使用 `/api/query/daily`。
- 日报归档使用 `/api/query/dailies`。

### 3.3 分类筛选

分类：

- 全部。
- 模型。
- 产品。
- 行业。
- 论文。
- 技巧。

规则：

- 分类值来自共享契约。
- 日报视图不使用 items 分类参数；日报按 section 展示。
- 切换分类后回到第一页。

### 3.4 时间窗筛选

选项：

- 今天。
- 昨天。
- 过去 24 小时。
- 最近 3 天。
- 最近 7 天。

规则：

- 前端传 `timePreset`，不自行计算 UTC。
- 如果用户需要超过 7 天，提示使用日报归档。

### 3.5 动态结果列表

每条卡片展示：

- 标题。
- 来源。
- 发布时间，缺失时显示“发布时间未知”。
- 分类。
- 摘要，缺失时显示“该条暂无摘要”。
- 原文链接。

展示规则：

- 点击标题或原文链接新窗口打开。
- 不展示 `null` 英文标题。
- 必须展示 `meta.warnings` 中的“原文为准”提示。
- 不补充 API 未返回的新闻事实。

### 3.6 日报视图

展示：

- 日期。
- lead 标题和导语。
- section 列表。
- 每条日报事件标题、摘要、来源、原文链接。
- flashes 列表，如果为空不展示。

行为：

- 支持输入或选择日期。
- 404 时展示“该日期暂无日报”。

### 3.7 日报归档视图

展示：

- 日期。
- 星期。
- 主标题。
- 事件数。

行为：

- 点击某个归档项切换到日报视图，并请求对应日期。

### 3.8 状态设计

必须支持：

- 首次进入态。
- 加载态。
- 空结果态。
- 可重试错误态。
- 不可重试错误态。
- 部分警告态。

错误展示：

- 展示 `error.message`。
- `error.retryable=true` 时展示重试按钮。
- 展示 trace id，便于排查。

## 4. 组件建议

组件命名可按项目实际风格调整，但职责应保持清晰：

- `QueryConsolePage`
- `QuerySearchBar`
- `ModeTabs`
- `CategoryFilter`
- `TimePresetControl`
- `ItemResultList`
- `ItemResultCard`
- `DailyReportView`
- `DailyArchiveList`
- `ApiStateView`
- `WarningBanner`

## 5. API 使用

以 `docs/contracts/query-api.md` 为唯一前后端契约。

前端调用：

```text
GET /api/query/items
GET /api/query/daily
GET /api/query/dailies
GET /api/query/help
```

前端不得调用：

```text
https://aihot.virxact.com/*
```

## 6. Mock 开发

前端可以先用 mock 数据开发，mock 必须覆盖：

- 精选有结果。
- 全部动态有结果。
- 分类有结果。
- 关键词空结果。
- 最新日报。
- 指定日期日报。
- 日报归档。
- 404 日报不存在。
- 503 可重试错误。
- 超时可重试错误。

Mock response 必须使用共享 envelope。

## 7. 验收标准

- 默认进入页面展示精选查询入口，不展示营销落地页。
- 用户可以切换精选 / 全部动态 / AI 日报 / 日报归档。
- 用户可以按分类、关键词、时间窗查询动态。
- 动态卡片每条至少展示标题、来源、原文链接。
- 无摘要、无发布时间时有明确占位文案。
- 空结果不报错。
- 错误态展示可读错误和 trace id。
- 可重试错误展示重试按钮。
- 前端不包含 AI HOT endpoint 常量。
- 移动端 375px 宽度下不出现文本互相覆盖。

## 8. 测试要求

- API client 参数构造测试。
- 分类和模式切换测试。
- 空状态测试。
- 错误态测试。
- 日报归档点击跳转测试。
- 结果卡片字段缺失测试。
- 基础响应式布局测试。

如果项目暂未配置前端测试框架，至少提供可运行的手动验收清单和 mock 数据。

## 9. 设计约束

- 工作台风格，信息密度优先，不做营销式 hero。
- 视觉应安静、可扫描，适合反复查看热点列表。
- 使用按钮、tab、筛选控件和明确状态提示。
- 不使用大段介绍性文案解释功能。
- 不使用前端写死新闻内容。
- 不把 AI 摘要写成已核验事实。

## 10. 联调边界

- 后端返回字段必须按契约，前端不做兼容多个后端字段名的 silent fallback。
- 契约不满足时，前端应暴露错误，不能静默吞掉字段缺失。
- 前端发现契约缺口时，先更新 `docs/contracts/query-api.md`，再更新实现。
