# M6 管理后台与规则 Brief

> 版本：v0.1
> 所属总 PRD：`prd.md`
> 阶段性质：路线级 brief，进入 M6 开发前需升级为详细 PRD
> 上游依赖：M2-M5 后端能力
> 下游依赖：M7 可观测闭环

## 1. 目标

提供管理后台，让管理员和审核员可以配置 source、规则、渠道，审核 topic，查看运行状态。M6 是把前面后台能力产品化。

## 2. 范围

### In Scope

- 数据源管理。
- 原始条目列表。
- 热点主题列表和详情。
- 合并/拆分操作入口。
- 价值评分与审核队列。
- 背景包与证据查看。
- 点评预览与编辑。
- 订阅规则与推送渠道管理。
- 推送历史。
- 用户与角色基础管理。
- 趋势分析页初版。

### Out of Scope

- 复杂多租户计费。
- 移动 App。
- 高级 BI 报表。
- 所有第三方渠道的深度卡片编辑器。

## 3. 输入与输出

输入：

- 后端 API：sources、raw-items、topics、assessments、background-packs、commentaries、subscriptions、channels、deliveries、reviews。
- 用户操作。

输出：

- 配置变更。
- ReviewDecision。
- AuditLog。
- 手动重跑请求。

## 4. 关键决策

- UI 按工作台产品，不做营销式页面。
- 事件簇详情页是核心页面。
- 所有写操作必须记录操作者、时间、旧值、新值和原因。
- 敏感值只脱敏展示。
- 需要登录和权限，具体认证方案进入详细 PRD 前冻结。

## 5. 验收标准

- 管理员可启停 source 并查看抓取状态。
- 审核员可批准、压制、编辑点评、合并、拆分、要求重跑。
- 事件簇详情能展示成员条目、评分、证据、点评、推送记录。
- 推送渠道密钥不明文展示。
- 所有人工动作写入 audit log。
- 前端移动宽度下不出现主要内容重叠。

## 6. 进入详细 PRD 前要补齐

- 认证方案：session/JWT/API token。
- RBAC 权限矩阵。
- 管理后台路由和页面信息架构。
- 写操作 API contract。
- 审核流状态机细节。
- 表单校验规则。
- 前端组件库或 UI 约定。
